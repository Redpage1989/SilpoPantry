# Де що лежить

Карта проєкту й правило, за яким він росте. Мета — щоб було очевидно,
куди класти новий файл і де шукати наявний.

## Одним поглядом

```
SilpoPantry/   — Next.js (App Router)
├── deploy/
├── docs/
│   ├── live-mcp-proof/
│   └── screenshots/
├── e2e/
├── prisma/
├── public/
├── scripts/
├── src/
│   ├── app/
│   ├── components/
│   └── lib/
├── test-results/
├── tests/
└── tutorial-out/
    └── slides/
```

## Куди що класти

| Що це | Куди | Ознака |
| --- | --- | --- |
| Сторінка | `src/app/<група>/` | має URL |
| HTTP-ендпоінт | `src/app/api/` | повертає дані, не розмітку |
| Візуальний елемент | `src/components/` | React, приймає props |
| Правило чи обчислення | `src/lib/` | не імпортує React |
| Тільки для сервера | `src/server/` | ключі, прямі звернення до БД |
| Зміна даних | `prisma/migrations/` | має діяти й повз інтерфейс |

## Ядро

Найзв'язніші вузли графа коду — те, чим користується решта:

| Вузол | Ребер |
| --- | ---: |
| `handle()` | 49 |
| `logEvent()` | 39 |
| `getUserId()` | 35 |
| `formatUah()` | 32 |
| `LiveSilpoAdapter` | 32 |

Новий код має спиратись на них, а не заводити паралельний спосіб
робити те саме.

## Перевірка
```bash
npm run typecheck
npm run test
npm run lint
npm run build
```

## Граф

`graphify-out/` містить граф коду. Питання про архітектуру дешевше
ставити йому, ніж грепати файли:

```bash
graphify query "як влаштована авторизація"
graphify explain "handle()"
```

Після змін коду — `graphify update .` (робить post-commit хук).

із них розходиться з наміром, виправляйте документ, а не код.*
